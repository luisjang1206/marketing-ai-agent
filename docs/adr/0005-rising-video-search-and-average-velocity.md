# 뜨기 직전 영상은 search.list 한 번과 평균 시간당 조회수로 판정한다

과제의 "시간당 150 이상"은 두 시점의 조회수 차이로 재는 쪽이 정확하지만, 그러려면 후보를 저장해 두고 수십 분 뒤 다시 조회해야 해서 버튼 한 번에 결과가 나오지 않고 시연 2~3분 안에 보여줄 수 없다. 그래서 시간당 조회수를 **조회수 ÷ 업로드 후 경과 시간(평균)** 으로 정의하고, Data API `search.list`(q=연애, type=video, order=date, 48시간 이내, 페이지당 100유닛) 뒤 `videos.list` 한 번으로 즉시 판정한다. 조회수가 5,000 이하이면서 시간당 150 이상이려면 업로드 후 33시간 이내여야 하므로, 48시간 창이면 빠지는 영상이 없다.

## Considered Options

- 두 시점 스냅샷: 정확하나 즉시성이 없다. 나중에 재검색에서 같은 영상이 다시 나오면 실측 증가율을 병기하는 식으로 덧붙일 수 있다.
- 허용 채널 업로드만 훑기: 1유닛이지만 후보가 30개 이하라 조건에 맞는 영상이 거의 없다. 과제가 "'연애' 키워드"를 명시한다.

## Consequences

- 클릭당 약 202유닛(페이지 2). 하루 할당량 10,000이면 약 49회. 자동 갱신은 하지 않는다.
- `videos.source`에 `'rising'`이 추가되어 기존 `data/agent.db`는 `pnpm reset:data`로 다시 만들어야 한다. `openDb`가 구 스키마를 감지해 이 안내를 던진다.
- 검색 결과는 `rising_searches` / `rising_candidates`에 남고, 화면은 최신 검색만 보여준다. 허용 채널 영상이 결과에 섞이면 기존 운영 규칙대로 게시할 수 있다(새 규칙 없음).
