# 시연 시나리오 (2~3분)

화면 녹화용 대본입니다. 설치와 설정은 [README](../README.md)를 먼저 끝내 둡니다. 게시는 **테스트 채널 영상에만** 합니다. 허용 채널 5개에는 게시하지 않습니다. 차단 시연은 허용 밖 영상 링크로 합니다. 뜨기 직전 컷은 선택이며, 이 컷에서도 게시하지 않습니다.

## 타임라인

전체 3:00 안에 선택 컷(15초)을 넣으려고 기존 컷 세 개를 줄였습니다(표의 길이 칸). 길이 합: 10 + 15 + 30 + 60 + 25 + 15 + 25 = 180초 = 3:00.

| 시각 | 길이 | 컷 | 하는 일 | 화면에서 보여야 할 것 |
|---|---|---|---|---|
| 0:00 | 10초 (15초에서 줄임) | 대시보드 한 바퀴 | 마우스로 ① → ② → ③ → 아래 게시 기록 순서로 짚습니다 | 번호 붙은 세 칸과 칸마다 한 줄 안내, "오늘 게시 0/10" 배지, 빈 게시 기록("아직 게시 기록이 없습니다") |
| 0:10 | 15초 (20초에서 줄임) | ① 영상 불러오기 | [불러오기]를 누릅니다 | 허용 채널 6개(과제 5개 + 테스트 채널)의 영상 카드(썸네일·제목·채널·올린 시각), 채널 칩과 "테스트" 배지 |
| 0:25 | 30초 | ② 영상 선택 | 테스트 영상 카드를 고릅니다. 스켈레톤이 도는 동안 기다렸다가 초안이 나오면 한 번 읽어 줍니다. [다시 생성]을 한 번 누릅니다 | **고민 한 줄**, **근거 장면**, **댓글 초안**과 글자수(N/120), "검증 통과" 배지, 자막 배지. [다시 생성] 뒤 문장이 바뀜 |
| 0:55 | 60초 | ③ 댓글 달기 | 프로필 선택에서 **유튜브2**를 고르고 [댓글 달기]를 누릅니다. 오른쪽에 크롬 창이 열려 한 글자씩 타이핑되고 등록되는 것을 보여 줍니다. 내 댓글이 하이라이트되면 대시보드로 시선을 옮깁니다 | 진행 상태 **프로필 여는 중 → 입력 중 → 게시 완료 → 댓글 보기**, 내 댓글이 하이라이트된 캡처와 [영상에서 보기], 배지 "오늘 게시 1/10", 게시 기록 맨 위의 "성공" 행 |
| 1:55 | 25초 | 차단 두 가지 | (a) 방금 그 영상을 다시 고릅니다. (b) ① 맨 아래 **링크 직접 입력**에 허용 채널이 아닌 영상 링크를 붙여넣고 [추가]를 누릅니다 | (a) [댓글 달기]가 꺼져 있고 툴팁·안내에 "이 영상에는 이미 댓글을 달았습니다". (b) 입력창 아래 빨간 "허용 채널의 영상이 아닙니다", 게시 기록에 "차단" 행("허용 채널의 영상이 아님") |
| 2:20 | 15초 (**선택 컷**) | 뜨기 직전 → 초안까지만 | ① 위쪽 토글을 **뜨기 직전**으로 바꾸고 [뜨기 직전 찾기]를 누릅니다. **허용 채널이 아닌** 후보 카드 하나를 고르고, ②에 초안이 나오면 한 줄만 읽은 뒤 ③의 꺼진 [댓글 달기]를 가리킵니다 | 토글 "뜨기 직전"과 안내 "'연애' 48시간 · 조회수 1,000~5,000 · 시간당 150+", 상태 줄 "마지막 검색 방금 전 · 훑은 영상 N개 · 후보 K개", 카드 배지 "조회수 N · 시간당 +M". ②에 고민 한 줄·근거 장면·초안. ③은 [댓글 달기]가 꺼지고 툴팁 "허용 채널의 영상이 아닙니다"와 안내 "뜨기 직전 영상은 초안까지만 만듭니다 (허용 채널 아님)" |
| 2:35 | 25초 (30초에서 줄임) | 게시 기록 · 제작 의도 | 게시 기록 표를 가리키며 제작 의도 한 줄을 말합니다 | 시각·영상·프로필(유튜브2)·댓글·결과·사유·캡처 열, 최신순으로 "차단"과 "성공" 행 |

- 1:55 (a): 이미 댓글을 단 영상은 버튼이 **미리 꺼지므로** 눌러서 만든 차단 행은 없습니다. 차단 행은 (b)에서 생깁니다. 서버는 (a)의 요청이 들어오면 똑같이 막고 기록합니다.
- (b)에 쓸 링크는 허용 채널이 아닌 아무 영상이면 됩니다. 이 링크는 어디에도 게시되지 않습니다.
- **선택 컷을 빼면** 마지막 컷이 2:20에 시작해 2:45에 끝납니다(길이 합 165초 = 2:45). 이때도 3분을 넘지 않으므로 줄인 컷 길이는 그대로 둡니다.
- 후보 중에는 과제 채널 5개나 테스트 채널의 영상이 섞일 수 있습니다. 그런 카드는 허용 채널 영상이라 [댓글 달기]가 켜지므로, 이 컷에서는 카드의 채널명이 `config.yaml`의 허용 채널과 다른 후보("테스트" 배지 없음)를 고릅니다.
- **선택 컷은 게시 기록에 행을 만들지 않습니다.** 초안만 만들고 [댓글 달기]는 꺼져 있어 시도 자체가 없기 때문입니다. 마지막 컷의 "차단"과 "성공" 행은 선택 컷을 넣든 빼든 같습니다.
- 검색(약 202유닛)과 초안 생성 대기가 있어 15초가 빠듯하면 편집에서 대기 구간을 잘라 냅니다.

### 멘트 가이드

1. "영상을 불러와서, 고르면 AI가 초안을 쓰고, 프로필을 골라 크롬으로 게시하는 세 칸입니다."
2. "허용 채널 다섯 개와 제 테스트 채널의 최신 영상을 한 번에 가져옵니다."
3. "초안만이 아니라 근거 장면을 같이 보여 줍니다. 이 영상의 이 장면을 짚은 댓글인지 사람이 바로 확인할 수 있습니다."
4. "실제 Chrome 프로필이 열리고, 사람처럼 한 글자씩 입력합니다. 등록 뒤에는 내 댓글이 보이는지 확인해서 캡처를 남깁니다."
5. "운영 규칙은 코드가 막습니다. 같은 영상에는 두 번 달 수 없고, 허용 채널이 아닌 링크도 막혀서 기록에 남습니다."
6. (선택 컷) "'연애'로 검색해서 조회수가 1,000에서 5,000 사이이고 시간당 150 이상 붙는, 막 뜨려는 영상을 찾습니다. 허용 채널이 아니면 초안까지만 만들고 게시는 막힙니다."
7. 제작 의도 한 줄: "맥락을 먼저 읽고, 시청자처럼 게시하고, 규칙은 코드가 지키게 했습니다."

## 녹화 전 체크

다시 찍을 때마다 처음부터 확인합니다.

1. **개발 서버를 끄고 `data/`를 비웁니다.** 프로필 폴더(`data/profiles/`)는 **지우지 않습니다.** 구글 로그인이 들어 있습니다.

   ```bash
   pnpm reset:data
   ```

   DB(`data/agent.db`), 캡처(`data/screenshots`), 자막 캐시(`data/captions`)를 지웁니다. 앱이 DB를 WAL 모드로 열기 때문에 `-wal`·`-shm` 파일도 같이 지웁니다(DB만 지우면 남은 파일이 새 DB와 짝이 맞지 않아 문제가 될 수 있습니다). 두 폴더는 다음 실행 때 앱이 다시 만듭니다. 자막을 다시 받느라 ②가 첫 번에는 몇 초 더 걸립니다.
2. **`pnpm dev`로 서버를 켜고 프로필 로그인 상태를 다시 채웁니다.** 로그인 상태는 DB에 저장돼 있어 1번에서 같이 지워집니다. `/settings`에서 **유튜브2**(가능하면 세 프로필 모두)의 [상태 확인]을 눌러 "로그인됨"과 채널 @핸들이 보이게 합니다. "로그인됨" 표시가 있어야 자동(돌아가며) 배정이 그 프로필을 고르고, 저장된 @핸들로 게시 뒤에 내 댓글을 찾습니다. 로그인이 풀려 있으면 [로그인 창 열기]로 다시 로그인한 뒤 확인합니다.
3. **테스트 영상을 정합니다.**
   - 시연에 쓸 테스트 채널 영상 하나의 ID를 메모해 두고, ① 목록에서 보이는지 확인합니다(없으면 링크 직접 입력으로 추가).
   - 리허설에서 그 영상에 단 댓글이 남아 있으면 **유튜브에서 직접 지웁니다.** DB를 비우면 영상당 1개 기록도 사라져 앱은 이미 달았다는 것을 모릅니다.
4. **키와 설정을 확인합니다.** `.env.local`에 키 2개가 있는지, `config.yaml`의 테스트 채널 ID가 실제 값인지 확인합니다. 키 값이 화면에 나오지 않게 합니다(터미널·편집기를 녹화 범위에서 뺍니다).
5. **화면과 창 배치.**
   - 화면 해상도 **1280×800**.
   - 대시보드 창은 **왼쪽**, 게시 때 열리는 크롬 창은 **오른쪽**에 두어 서로 가리지 않게 합니다. 크롬 창은 프로필별로 마지막 위치를 기억하는 편이니, 리허설에서 한 번 옮겨 두고 같은 위치에 열리는지 확인합니다.
   - 대시보드는 창 너비가 1024px(CSS 기준) 미만이면 세 칸이 위아래로 쌓입니다. 왼쪽 창이 좁으면 브라우저 배율을 낮춰 세 칸이 나란히 보이는지 리허설에서 확인합니다.
6. **(선택 컷을 찍을 때) 뜨기 직전 검색을 확인합니다.** 버튼 한 번에 YouTube 할당량을 약 202유닛 쓰므로(하루 10,000이면 약 49번) 리허설에서 눌러 보는 횟수를 아낍니다. 조건에 맞는 영상이 없으면 "조건에 맞는 영상이 없습니다"가 나오니, 그때는 시간을 두고 다시 찾거나 선택 컷을 뺍니다. `pnpm reset:data`는 검색 기록도 지우므로, 녹화 직전에 지웠다면 컷 안에서 [뜨기 직전 찾기]를 직접 눌러야 후보가 보입니다.
7. **시작 상태를 확인합니다.** 대시보드 맨 위가 "오늘 게시 0/10", 게시 기록이 비어 있고, ①에 영상이 아직 없는 상태(① [불러오기]를 컷 2에서 누릅니다)에서 녹화를 시작합니다. 알림·메신저 창은 닫습니다.
